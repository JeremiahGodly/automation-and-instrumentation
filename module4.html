Part 1 · Syllabus Theory

4.1 Introduction and organisation of a PLC

A programmable logic controller (PLC) is a rugged, special-purpose industrial computer that reads inputs (switches, sensors), executes a user-written control program stored in memory, and sets outputs (motors, valves, lamps) to control a machine or process. PLCs were introduced in 1968 (by General Motors, with Modicon 084) to replace hard-wired relay logic panels. Compared to relay panels, the PLC is smaller, cheaper for large systems, far easier to modify (change the program, not the wiring), more reliable (no moving parts), has self-diagnostics, and can do arithmetic, timing, counting, PID control and communication.

A PLC is organised as a number of functional blocks connected by internal buses: the CPU (processor and memory), the input/output modules, the power supply, and the programming device. In a modular (rack) PLC, these units are plugged into a backplane; compact PLCs have everything in one box. The CPU communicates with the other units through the data bus (carrying data, 8/16 bits), the address bus (identifying the memory location or I/O address), the control bus (read/write, timing and clock signals) and the system bus (I/O communication).

4.2 Hardware details – I/O, power supply and CPU

Central processing unit (CPU)

The CPU is the "brain" of the PLC. It consists of the microprocessor (with ALU and registers), the system clock, and the memory. It performs: (i) fetching and executing the user program, (ii) reading the input states and writing outputs, (iii) arithmetic, logic, timing, counting and data-handling operations, (iv) communication with the programming device, HMI and other PLCs over serial/Ethernet links, and (v) self-diagnostics and watchdog monitoring – a watchdog timer resets the CPU if the scan takes too long. The CPU works in the repeated scan cycle: input scan (copy the inputs into the input image table) → program scan (execute the ladder from the first to the last rung, using the image table) → output scan (copy the output image table to the output modules) → housekeeping (communications, diagnostics). The scan time is of the order of 1–100 ms and determines the response speed. Memory comprises ROM/EPROM for the operating system (executive), RAM (battery backed) for user program and data, and EEPROM/Flash for program backup.

Input/output (I/O) modules

I/O modules connect the field devices to the CPU and also condition the signals. Input modules accept discrete signals (24 Vdc, 120/230 Vac) or analog signals (4–20 mA, 0–10 V, thermocouple/RTD) and, using opto-isolators, convert them to the logic level (5 V) of the CPU while separating the electronics from field voltages and noise. Output modules drive the loads: relay outputs (any load AC/DC, slow, 2 A, contacts wear), transistor outputs (DC only, fast, long life) and triac outputs (AC loads, no moving parts), also isolated optically. Analog outputs (4–20 mA, 0–10 V) are provided through D/A converters, and special modules exist for high-speed counting, positioning, PID and communication. Each I/O point has a unique address and indicator LED.

Power supply

The power supply converts the mains (230 V AC, or 24 V DC) to the DC levels (5 V, 12 V, 24 V) required by the CPU and I/O modules, regulated and with protection against surges, brown-outs and noise. It also supplies a battery back-up for RAM and the real-time clock. Its importance is in giving a clean, stable supply so that the CPU operates reliably, the program memory is not lost on power failure, and fluctuations do not cause false operation. The field devices are often powered from a separate 24 V DC supply.

4.3 Programming standards and aspects

The international standard IEC 61131-3 defines five PLC programming languages so that programs are portable between vendors: Ladder Diagram (LD) – graphical, resembling relay circuits; Function Block Diagram (FBD) – graphical blocks connected by signal lines; Structured Text (ST) – high-level, Pascal-like; Instruction List (IL) – low-level assembler-like (mnemonics such as LD, AND, OR, ST); and Sequential Function Chart (SFC) – step/transition chart for sequential processes. Ladder logic is the most popular since electricians can understand it easily.

Ladder programming basics

A ladder diagram has two vertical rails (power rails, representing the supply lines: left rail is the live, right rail is neutral/0 V) and rungs between them which are horizontal lines carrying the logic. Each rung contains inputs (contacts) at the left (examining bits in the memory) and an output (coil) at the right. Series elements represent AND, parallel branches represent OR. Contacts are input elements (instructions that test the status of a bit: XIC or XIO) and coils are output elements (instructions that set a bit: OTE, OTL, OTU) – and timers, counters and math blocks are also placed in the rung as output-type instructions.

4.4 Realisation of logic gates – AND, OR, NAND, XOR and latching

AND: two NO contacts in series. The output is on only if both A and B are on. OR: two NO contacts in parallel. The output is on if either is on. NOT: a single NC contact. NAND: output is OFF only if both inputs are ON, i.e. $Y=\overline{A\cdot B}=\bar A+\bar B$ → two NC contacts in parallel. NOR: $Y=\overline{A+B}=\bar A\cdot\bar B$ → two NC contacts in series. XOR: $Y=A\bar B+\bar A B$ → two series pairs (A with NC B, NC A with B) in parallel.

The concept of latching (seal-in)

A momentary push button should start a motor that then keeps running after the button is released. This latching (holding or sealing) is obtained by using the output's own contact in parallel with the start push-button: once the output turns on, its contact closes and provides an alternative path (a "hold-in" circuit), so the output remains energised even when the Start input opens. The Stop button is a NC contact in series that breaks the path and "unlatches" the output. Alternatively, the set (latch, OTL) and reset (unlatch, OTU) instructions can be used; latched outputs are retained even after power failure in some PLCs, which is important for safety.

4.5 Timers and counters

Timers. A PLC timer is an internal software instruction replacing a hardware time-delay relay. It has a time base (0.001, 0.01, 0.1 or 1 s), a preset value (PRE/PV) – the number of time-base intervals to be counted, an accumulated value (ACC) – the elapsed time since the timer was last reset, which is updated continuously while the timer is enabled, and status bits: enable (EN), timer timing (TT) and done (DN), which is set when ACC reaches PRE. The delay time is $T = \text{PRE}\times\text{time base}$ (e.g. PRE = 1000 with time base 0.1 s gives 100 s). Types: TON – on-delay: starts timing when the rung becomes true and the output goes on after the preset time, and resets when the rung goes false; TOF – off-delay: output goes on immediately and stays on for the preset time after the rung goes false; RTO (retentive) – keeps its accumulated value when the rung becomes false and must be reset with a separate RES instruction; the pulse timer gives a fixed-length output pulse.

 TON timer example  (delay of 10 s with 0.1 s base: PRE = 100)
 |--| |-----------------------[ TON  T4:0   Base 0.1   PRE 100  ACC 0 ]--(EN)(DN)--|
 |  I:0/0 (enable)
 |--| |---T4:0/DN-----------------------------------------------------( )----------|
                                                                       O:0/0  (turns on 10 s after I:0/0 closes)

Counters. A counter counts the number of transitions (events) of a input contact (false→true), such as the number of items passing a sensor. Parameters: preset (PRE), accumulated (ACC) and bits: CU/CD (count up/down enable), DN (done: ACC ≥ PRE), OV/UN (overflow/underflow). CTU counts up on every rising edge, CTD counts down, and CTUD does both. A counter retains its value even when the rung goes false, and so it must be cleared with a separate RES (reset) instruction. Counting is done by software on the sensor signal, so it is more reliable and accurate than mechanical counters, and each cycle is detected only once per scan (the maximum count rate is limited by scan time; high-speed counter modules are used above that).

Significance of timers and counters

Timers provide time-based control: delays, sequential start-up, flashing lamps, motor run-on, and cycle timing. Counters give event-based control: counting parts, batching, tracking positions and limiting the number of operations. Together they permit sequential control of complex processes and they are far more flexible than hardware timer relays and counters because the preset can be changed in software and they give multiple contacts for free.

Ladder programming is a graphical PLC language (LD in IEC 61131-3) that resembles the relay ladder wiring diagram, and is named so because the diagram looks like a ladder. Its elements are: (1) Rails – two vertical lines on left and right giving the power flow to the logic; (2) Rungs – horizontal lines between the rails, each rung containing one logical operation (one or more input conditions and an output); (3) Branches – parallel paths in a rung representing OR logic; (4) Inputs (input elements) – contacts, normally open (XIC) or normally closed (XIO), which examine the status of physical input devices (push buttons, limit switches, sensors) or internal bits; (5) Outputs (output elements) – coils that drive physical outputs (motor starters, lamps, solenoids) or internal bits; (6) Timers/counters and functional blocks. A rung is solved from left to right; if there is a continuous logical path ("power flow") the output is energised. Sample program (start/stop motor):

 |  Start   |  Stop    Motor     Stop (I0.1) in series breaks the circuit.
 |--+--| |--'

Give the significance of timers and counters in PLC.

3 marks
Jun 2023 · Q7Apr 2026 · Q8 (counters)

Timers provide a variety of time bases (usually 0.01 s, 0.1 s and 1 s). Each timer has an accumulated value (ACC), which is the time elapsed since the timer was last reset, and which is updated continuously when the timer is enabled, and a preset value (PRE), which specifies the value that the timer must reach before the controller sets the done bit. Timers give delays, sequencing and timing of process operations. A counter uses a sensor signal to count operations or events (objects, revolutions), which is processed by software in the PLC; thus failure rate is reduced and accuracy is increased compared with hardware counters. Counters (CTU, CTD) set a done bit when the count reaches the preset and are used for batching, packaging, inventory and limit control. The major difference is that a timer continuously increments its accumulated value at a rate fixed by the time base while the enable contact is on, whereas the counter increments only on each false-to-true transition of its input.

Discuss latching in PLC.

3 marks
Apr 2025 · Q7

Latching is a program technique by which an output, once switched on by a momentary input (e.g. a Start push-button), stays on after the input is released, until a separate reset or stop action. It is accomplished by connecting a normally-open contact of the output itself in parallel with the start contact (a seal-in or holding contact) while a normally-closed stop contact is connected in series in the rung. When Start is pressed, the output energises and its own contact closes, thereby providing a parallel path; releasing Start does not open the circuit. Pressing Stop opens the path, and the output drops off, and also the seal-in contact opens. Alternatively, the OTL (latch/set) and OTU (unlatch/reset) instructions can be used. Latching is used for motor start–stop circuits, alarms (latched until acknowledged) and for holding conditions in sequences.

1. Central processing unit (CPU). The CPU contains the microprocessor which executes the program stored in the memory, controls all activities in the PLC, performs the logical and arithmetic operations, and carries out the scan cycle of reading the inputs, solving the program and updating the outputs. It includes a clock, which sets the timing of operations, and carries out diagnostics.

2. Memory. ROM holds the permanent operating system (monitor/executive) and cannot be changed by the user. RAM (with battery backup) holds the user program, the data (timer and counter values, internal relays), and the input/output image tables. EPROM/EEPROM/Flash store the program permanently or for backup.

3. Input interface (module). Connects the field input devices – push-buttons, limit switches, proximity sensors, analog transmitters – to the CPU. It converts the field signals (24 V DC/120 V AC/4–20 mA) into the logic level (5 V) and provides optical isolation to protect the CPU from voltage spikes and noise, and also performs filtering.

4. Output interface (module). Gets the CPU's decisions to the actuators – contactor coils, solenoids, lamps, valves – via relays, transistors or triacs, while giving electrical isolation. Analog outputs come through D/A converters.

5. Power supply. Converts the AC mains to the DC voltages required by the processor and the I/O modules and provides regulated, filtered power, and battery back-up.

6. Programming device and communication interface. A PC or handheld programmer is used to enter, edit, monitor and debug the ladder program, which is then downloaded to the PLC memory. The communication ports (RS-232/485, Ethernet, Profibus) connect the PLC to HMIs, SCADA and other PLCs.

Buses. The units are linked with three sets of parallel lines: the address bus (carries the address of the memory location or I/O channel to be accessed, e.g. 16 lines allow 64 K locations), the data bus (carries the data being transferred, 8/16/32 bit) and the control bus (carries the control signals – read, write, clock, interrupt – that synchronise the operation). A system bus is used for I/O communication. The CPU is the bus master.

Q. Importance of the power supply in a PLC and importance of the CPU in a PLC.

6 marks each
Jun 2023 · Q17(b) (power supply)Jun 2023 · Q18(b) (CPU)

(a) Importance of the power supply

The PLC power supply converts the incoming 230 V/110 V AC (or 24 V DC) into regulated DC voltages (typically 5 V for logic, ±12 V, and 24 V) needed by the CPU, memory, I/O modules and communication circuits. Its quality decides the reliability of the whole controller. (i) Stable voltage: processors and memory need a well-regulated supply; a change in supply voltage may cause wrong operation or corrupt data. (ii) Filtering and protection: it filters line noise and spikes and protects against surges, over-voltage, over-current and short circuit. (iii) Hold-up time and brown-out detection: during a short power dip, it holds the voltage for several ms so that the CPU can save its state or shut down safely. (iv) Battery backup: supports RAM contents (user program, retentive data), and the real-time clock during power failure. (v) Isolation between mains and logic voltages for safety. (vi) Supply to field devices: many PLCs offer a 24 V DC auxiliary output for sensors. Therefore a properly sized, clean supply is essential for the dependable, safe operation of the PLC; the supply should be rated 20–30 % above the total load.

(b) Importance of the CPU

The CPU is the heart and brain of the PLC and controls everything that takes place within the system. It contains the microprocessor chip, system clock and memory, and its major roles are: (i) Executing the user program – fetching each instruction from memory, decoding and executing it, solving logic, arithmetic, timer, counter, comparison, data-move and PID operations, in the repetitive scan cycle (input scan → program scan → output scan). (ii) Controlling data transfer over the address, data and control buses between memory and I/O. (iii) Managing memory – the ROM operating system, the user RAM, and the I/O image tables. (iv) Communication with the programming device, HMIs, other PLCs and networks. (v) Self-diagnosis and fault handling – watchdog timer, memory and I/O checks, fault indicators, mode control (RUN/PROG/TEST). (vi) Timing – the clock determines scan speed; scan time of a few ms decides how fast the controller reacts. The processing power and memory size of the CPU decide the number of I/O points, programme size and complexity that the PLC can handle, so its selection is the first step when choosing a PLC.

Explanation. In the ladder logic, series contacts act as AND and parallel contacts as OR. Q. Explain the working of counters in a PLC with an example (and mention applications).

6 – 8 marks
Jun 2023 · Q17(a) (8)May 2024 · Q18(a) (6)Apr 2025 · Q17(b) (6)

A counter is a PLC instruction that counts the number of occurrences of an event, each event being a false-to-true (rising edge) transition of the input rung. In place of mechanical or electromechanical counters, it uses a sensor to detect operations, which are processed by software, so the failure rate is reduced and accuracy is increased. Every counter has a preset value (PRE), which is the number of counts to be reached; an accumulated value (ACC) which is the number of counts so far; and the status bits CU (count-up enabled), CD (count-down enabled), DN (done – set when ACC ≥ PRE), and OV/UN (overflow/underflow).

Types of counters. (i) Up counter (CTU): ACC increases by 1 on each false→true transition; DN is set when ACC ≥ PRE. (ii) Down counter (CTD): ACC decreases by 1 each time; DN is true while ACC ≥ PRE (preloaded) or set when ACC reaches 0 depending on the PLC. (iii) Up/down counter (CTUD): counts up on CU and down on CD, useful for keeping the inventory of items in a bin. (iv) High-speed counter: hardware module for pulses faster than the scan rate, such as encoder signals. The counter does not reset automatically when its rung goes false; it must be reset by a RES instruction with the same address, which sets ACC to zero and clears DN.

Example – counting 10 bottles and then starting a packing machine.

 Rung 1 : count bottles (I0.0 = photo-sensor)
 |---| |---------------------------[ CTU  C5:0   PRE 10   ACC 0 ]---|   (counts each bottle that passes)
     I0.0
 Rung 2 : action when the preset is reached
 |---| |--- C5:0/DN ---------------------------------------------( )--|   Q0.0 = Packing machine / conveyor stop
 Rung 3 : reset the counter (manual reset or after packing)
 |---| |--- I0.1 (Reset PB) --------------------------------------[RES C5:0]--|

Each time a bottle interrupts the light beam, I0.0 goes from 0 to 1 and the count ACC increases by one. After 10 bottles ACC = PRE = 10, the done bit C5:0/DN becomes true, and the output Q0.0 starts the packing machine. When packing is finished, the reset push button I0.1 executes RES and the counter is ready again. Applications: counting products on a conveyor, batch filling, packaging, parking lot vehicle counting, rotation counting of shafts, limiting the number of cycles of a machine, and keeping stock levels (up/down counting).

Q. Explain various timers in PLC / the classification of timers (two types of timers).

6 marks
May 2024 · Q17(a)Apr 2025 · Q18(b)Apr 2026 · Q18(b)

A timer in a PLC is a software instruction which provides time delays by counting pulses of a clock (time base) and comparing the count with a preset value. It replaces mechanical or pneumatic time-delay relays. The parameters are the time base (e.g. 0.01, 0.1, 1 s), preset (PRE), accumulated value (ACC), and the bits EN (timer enable), TT (timing in progress) and DN (done). The total delay is $T = \text{PRE}\times\text{time base}$.

1. On-delay timer (TON). When the input rung becomes true, the timer begins counting; the ACC rises until it equals PRE, then DN is set and the associated output is energised after the delay. If the rung goes false before the preset is reached, the timer resets (ACC = 0, DN = 0). It is used to delay the start of a device, e.g. starting a second motor 10 s after the first.

 Input   ____|-----------------------|______       TON: output comes ON t seconds after the input
 Output  ________________|-----------|______       turns ON; both drop when input drops.
                  |<-- delay t -->|

2. Off-delay timer (TOF). The DN bit is set as soon as the rung becomes true, and when the rung goes false the timer starts timing; the output remains ON for the preset time after the input goes OFF, and then switches off. Used to keep a cooling fan running after the motor has stopped.

 Input   ____|----------|____________________     TOF: output turns ON immediately and stays ON for
 Output  ____|---------------------|__________    t seconds after the input turns OFF.
                        |<-- delay t -->|

3. Retentive on-delay timer (RTO). Works like a TON but retains its ACC value when the rung goes false or on power loss, resuming when the rung becomes true again, until it is reset by an RES instruction. Used for accumulating the total running time of a machine (maintenance scheduling).

4. Pulse timer (TP) and cyclic/flasher timer: TP gives an output pulse of fixed duration on a trigger; two TONs can be combined to give a repeating flasher.

The following ladder example is a 10 s on-delay: when I0.0 closes, the timer T4:0 (0.1 s base, PRE = 100) starts, and 10 s later T4:0/DN energises the output Q0.0.

Q. Devise a ladder program to switch on a pump for 100 s; it is then switched off and a heater switched on for 50 s. Then the heater is switched off, and another pump is used to empty the water.

8 – 14 marks
May 2024 · Q18(b) (8)Model Q17 (14)

The process is a three-step sequence: (1) Pump 1 fills the tank for 100 s; (2) Pump 1 is switched off and the heater on for 50 s; (3) the heater is switched off and Pump 2 empties the tank. It is a timed sequential control problem solved with two on-delay timers and latched (seal-in) internal states.

I/O assignment: I0.0 – Start push-button (NO); I0.1 – Stop push-button (NC wired as NO input, used as XIO in rung 1 & 5); Q0.0 – Pump 1 (filling); Q0.1 – Heater; Q0.2 – Pump 2 (emptying); M0.0 – Sequence running (latch); T1 – TON 100 s (PRE = 1000, 0.1 s base); T2 – TON 50 s (PRE = 500, 0.1 s base).

 Rung 1 : Start/stop latch for the sequence
 |--+--| |--+--|/|----------------------------( )--|
 |  I0.0    |  I0.1                           M0.0 (RUN)
 |--+--| |--'
    M0.0

 Rung 2 : Pump 1 ON for 100 s   (RUN and timer T1 not done)
 |--| |--------|/|----------------------------( )--|
    M0.0       T1.DN                          Q0.0 (Pump 1)

 Rung 3 : Timer T1 – 100 s starts with RUN
 |--| |------------------------------[ TON T1   PRE 1000 (0.1 s) ]--|
    M0.0

 Rung 4 : Heater ON for 50 s  (after T1 done, until T2 done)
 |--| |--------| |--------|/|-------------( )--|
    M0.0       T1.DN      T2.DN           Q0.1 (Heater)

 Rung 5 : Timer T2 – 50 s starts when T1 is done
 |--| |------------------------------[ TON T2   PRE 500 (0.1 s) ]--|
    T1.DN

 Rung 6 : Pump 2 empties the tank (after T2 done)
 |--| |--------| |-----------------------( )--|
    M0.0       T2.DN                      Q0.2 (Pump 2)

Operation. Pressing Start sets the latch M0.0 (rung 1). In rung 2, Pump 1 (Q0.0) runs because M0.0 is true and T1.DN is false, while T1 begins timing 100 s in rung 3. At 100 s, T1.DN becomes true: Pump 1 turns off (rung 2 opens), the heater Q0.1 turns on (rung 4) and T2 starts timing 50 s (rung 5). At 50 s, T2.DN becomes true: the heater is switched off (rung 4 opens) and Pump 2 (Q0.2) turns on, to empty the tank (rung 6). The Stop button drops M0.0, resets both timers and all outputs. A level switch NC contact for "tank empty" can be added in series with M0.0's latch to end the cycle automatically.
